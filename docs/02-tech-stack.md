# 2. Tech stack

## 2.1 What the app uses

| Layer | Technology | Purpose |
|---|---|---|
| Desktop shell | **Tauri 2** | Native window, packaging, IPC, plugins |
| Backend | **Rust (stable)** | Processes, PTY, reading/writing configuration |
| PTY | **`portable-pty`** (crate, uses ConPTY) | Host shells as real terminals |
| Concurrency | Dedicated reader/waiter threads per session | Stream each PTY's output without blocking |
| Serialization | **`serde` / `serde_json`** | Settings, themes and IPC messages |
| Shell detection | **`winreg`**, PATH lookup, `wsl.exe -l -q` | Find Git Bash, pwsh, WSL distros |
| Process inspection | **`windows-sys`** (Toolhelp32) | Detect programs running inside a shell before closing it |
| Errors | **`thiserror`** | Typed backend errors, serialized as readable messages |
| Logging | **`log`** + `tauri-plugin-log` | Log files for troubleshooting (backend and UI errors) |
| Frontend | **React 19 + TypeScript** | Interface |
| Frontend build | **Vite** | Dev server and production build |
| Terminal emulator | **xterm.js 6** (`@xterm/xterm`) | Render the terminal (ANSI, colors, cursor, selection) |
| xterm addons | `addon-fit`, `addon-webgl`, `addon-search`, `addon-web-links`, `addon-unicode11` | Resizing, GPU rendering, search, clickable links, emoji/CJK width |
| State | **Zustand** | Tabs, active session, settings, UI state, themes, keybindings |
| Styling | **Plain CSS + CSS variables** | Themes switch live by changing variables |
| i18n | **i18next + react-i18next** | Languages (pt-BR, en-US, es-ES) |
| Validation | **zod** (frontend) / `serde` + checks (backend) | Validate `settings.json` sections and imported themes |
| Tauri plugins | `dialog`, `opener`, `log`, `single-instance`, `window-state` | File pickers, opening links/folders, logging, single instance, remembering window size |
| Frontend tests | **Vitest** | Unit tests for stores, layout, themes, keybindings, settings |
| Backend tests | **`cargo test`** (+ `tempfile`) | Unit and integration tests, including real PTY sessions |
| Lint/format | **ESLint, Prettier, `cargo clippy`, `rustfmt`** | Code quality |
| Package manager | **pnpm** | JS dependencies |
| CI/CD | **GitHub Actions** (`windows-latest`) + `tauri-action` | Tests, build and draft releases |
| Installers | **NSIS** and **MSI** (WiX), generated by Tauri | Distribution |

Planned, not in use yet: `tauri-plugin-updater` (auto-update), WebdriverIO + `tauri-driver` (E2E tests).

## 2.2 Why Tauri and not Electron?

| Criterion | Tauri 2 | Electron |
|---|---|---|
| Installer size | ~2–15 MB (Nexus: ~1.8 MB NSIS) | ~80–150 MB |
| Idle RAM | ~40–80 MB | ~150–300 MB |
| Web engine | WebView2 (Edge, ships with Windows 10/11) | Bundled Chromium |
| Backend language | Rust | Node.js |
| PTY | `portable-pty` (ConPTY) | `node-pty` (ConPTY), native module to compile |
| Learning curve | Steeper (Rust) | Gentler (JS only) |

**Decision:** Tauri, because a terminal manager stays open all day and memory usage matters. xterm.js works the same in both, so the interface would not change.

**Valid alternative:** Electron + node-pty + xterm.js. The architecture in this documentation still applies: replace "Tauri commands" with "Electron IPC (`ipcMain`/`ipcRenderer` via `contextBridge`)".

## 2.3 Why xterm.js?

It is the emulator used by the VS Code terminal, Hyper and many others. It supports full VT100/xterm, 24-bit color, mouse, links, selection, search and GPU rendering (WebGL). Writing a custom emulator would take months.

## 2.4 Why ConPTY (`portable-pty`)?

Since Windows 10 1809, ConPTY is the official way to host a shell as a terminal. Without it, programs like `vim`, `htop`, progress bars and colors do not work properly. `portable-pty` (from the WezTerm project) exposes it through a simple interface: `openpty`, `spawn_command`, reader, writer and `resize`.

## 2.5 End-user requirements

- Windows 10 version 1809 (build 17763) or later, or Windows 11.
- WebView2 Runtime (ships with Windows 11; the installer downloads it on Windows 10 if missing).
- The shells the user wants to use (e.g. Git for Windows for Git Bash).
